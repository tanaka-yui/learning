# 10-3 ECS vs k8s — 設計仕様

- 作成日: 2026-07-01
- 章: `10_container/03_ecs_vs_k8s/`
- 関連: `10-1` (image 流用)、`10-2` (kind cluster 思想流用)

## 目的

AWS ECS と Kubernetes の概念対応を 5 軸 (workload / network / storage / auth+secret / autoscale) で網羅し、同一 demo-app を「LocalStack 上の ECS」と「kind 上の k8s」で並行動作させて差分を体感する。

## スコープ

- Docs (5 軸対応表 + 解説 + 意思決定マトリクス)
- Terraform 雛型 (ECS)
- LocalStack で部分実証 (ECS Cluster / Task / Service / ECR)
- k8s manifests (Deployment / Service / Ingress / HPA / PVC)
- 同一 demo-app image を双方で起動して curl 比較

スコープ外:
- 実 AWS アカウントへのデプロイ
- ALB (LocalStack Pro 限定) — Terraform 雛型として書くが LocalStack 検証はスキップ
- EKS / Fargate Spot の深掘り

## 5 軸マッピング骨子

### 1. Workload (`docs/01-workload-mapping.md`)

| 概念 | ECS | k8s |
|---|---|---|
| 実行単位 | Task (1+ container) | Pod (1+ container) |
| 上位コントローラ (常駐) | Service (replica/daemon) | Deployment / DaemonSet / StatefulSet |
| 単発実行 | RunTask | Job |
| 定期実行 | Scheduled Task (EventBridge) | CronJob |
| クラスタ | ECS Cluster | k8s Cluster |
| 配置選択 | Capacity Provider (FARGATE/FARGATE_SPOT/EC2 ASG) | NodeSelector / Affinity / Taint+Toleration |
| サイドカー | Task 内 container を並べる | Sidecar container / native sidecar (k8s 1.28+) |
| 初期化 | dependsOn + healthCheck | initContainer |

### 2. Network (`docs/02-network.md`)

| 概念 | ECS | k8s |
|---|---|---|
| Pod/Task ネットワーク | awsvpc (ENI per task) / bridge (EC2) / host | CNI 抽象 (Cilium/Calico/Flannel) |
| 内部公開 | Service Discovery (CloudMap) | Service (ClusterIP) + CoreDNS |
| 外部公開 (L4) | NLB target=IP | Service type=LoadBalancer |
| 外部公開 (L7) | ALB target=IP | Ingress / Gateway API |
| サービス間 mesh | Service Connect (Envoy ベース) | Istio / Linkerd / Cilium (10-2) |
| ネットワークポリシ | Security Group (ENI 単位) | NetworkPolicy / CiliumNetworkPolicy |

### 3. Storage (`docs/03-storage.md`)

| 概念 | ECS | k8s |
|---|---|---|
| エフェメラル | Task ephemeral storage (Fargate 20-200GiB 設定可) | emptyDir |
| Host bind | volumes (bindMount on EC2) | hostPath |
| 共有ファイル | EFS volume | NFS PV / EFS CSI |
| ブロック | EBS volume attachment (新機能) | EBS CSI + StatefulSet |
| 動的 provision | (限定的) | StorageClass + CSI |

### 4. Auth + Secret (`docs/04-auth-secrets.md`)

| 概念 | ECS | k8s |
|---|---|---|
| 実行 IAM | Task Role (アプリ) + Execution Role (ECR/log pull) | ServiceAccount |
| クラウド側との認可 | Task Role がそのまま STS credential | IRSA (EKS) / Workload Identity (GKE) |
| シークレット | SecretsManager/SSM ARN を `secrets` で env 注入 | Secret + External Secrets Operator (ESO) |
| 暗号化 | 自動 (KMS) | etcd 暗号化 (EncryptionConfiguration) + Secret 自体は base64 のみ |

### 5. Autoscale (`docs/05-autoscale.md`)

| 概念 | ECS | k8s |
|---|---|---|
| ワークロード水平 | Service AutoScaling (Application Auto Scaling, Target/Step) | HPA (metrics-server / KEDA) |
| ワークロード垂直 | (ECS 単体無、Compute Optimizer 提案のみ) | VPA |
| ノード水平 | Capacity Provider (EC2 ASG) / Fargate (自動) | Cluster Autoscaler / Karpenter |
| イベント駆動 | EventBridge → RunTask | KEDA (Kafka/SQS/Cron/HTTP) |

### 6. Fargate vs Node (`docs/06-fargate-vs-node.md`)

- Fargate: サーバレス、課金粒度=vCPU/メモリ秒、Spot あり
- k8s 対応: GKE Autopilot / EKS Fargate Profile / Karpenter + Spot
- 設計: latency / cost / cold-start 比較表

### 7. Decision Matrix (`docs/decision-matrix.md`)

| 要件 | ECS 有利 | k8s 有利 |
|---|---|---|
| AWS only / 学習コスト低 | ◎ | △ |
| マルチクラウド / OSS エコ | △ | ◎ |
| 高度な mesh / Operator | △ | ◎ |
| サーバレス志向 | ◎ (Fargate) | ◎ (Autopilot/Karpenter) |
| IaC 統一 | Terraform | Terraform / Helm / Kustomize |

## Terraform (`terraform/ecs/`)

`main.tf` (要点):

```hcl
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}

provider "aws" {
  region                      = "us-east-1"
  access_key                  = "test"
  secret_key                  = "test"
  skip_credentials_validation = true
  skip_metadata_api_check     = true
  skip_requesting_account_id  = true
  s3_use_path_style           = true
  endpoints {
    ecs = var.endpoint
    ecr = var.endpoint
    iam = var.endpoint
    logs = var.endpoint
  }
}

resource "aws_ecs_cluster" "this" { name = "learning-ecs" }

resource "aws_iam_role" "task" {
  name               = "ecsTaskRole"
  assume_role_policy = jsonencode({
    Version = "2012-10-17",
    Statement = [{ Effect = "Allow", Principal = { Service = "ecs-tasks.amazonaws.com" }, Action = "sts:AssumeRole" }]
  })
}

resource "aws_ecs_task_definition" "api" {
  family                   = "demo-api"
  network_mode             = "awsvpc"
  requires_compatibilities = ["FARGATE"]
  cpu                      = "256"
  memory                   = "512"
  task_role_arn            = aws_iam_role.task.arn
  execution_role_arn       = aws_iam_role.task.arn
  container_definitions    = jsonencode([{
    name      = "api"
    image     = "${var.ecr_repo}:v1"
    essential = true
    portMappings = [{ containerPort = 8080, protocol = "tcp" }]
  }])
}

resource "aws_ecs_service" "api" {
  name            = "api"
  cluster         = aws_ecs_cluster.this.id
  task_definition = aws_ecs_task_definition.api.arn
  desired_count   = 2
  launch_type     = "FARGATE"
  network_configuration {
    subnets         = var.subnets
    security_groups = var.security_groups
    assign_public_ip = true
  }
}
```

`variables.tf` に `endpoint = "http://localhost:4566"` (LocalStack) と本物 AWS 切替可能化。

## LocalStack (`localstack/`)

`docker-compose.yml`:

```yaml
services:
  localstack:
    image: localstack/localstack:3
    ports: ["4566:4566"]
    environment:
      SERVICES: ecs,ecr,iam,logs,cloudwatch
      DEBUG: "1"
    volumes:
      - "/var/run/docker.sock:/var/run/docker.sock"
```

`seed.sh`:

```sh
#!/bin/sh
set -e
AWS="aws --endpoint-url=http://localhost:4566"
$AWS ecr create-repository --repository-name demo-api || true
REPO=$($AWS ecr describe-repositories --repository-names demo-api --query 'repositories[0].repositoryUri' --output text)
docker build -t "$REPO:v1" ../demo-app/api
docker push "$REPO:v1"
echo "$REPO"
```

注: LocalStack Community で ECS API 操作は可能だが、実際の Task コンテナ起動は LocalStack のホスト Docker 経由で simulate される。ALB は Pro 限定のため、本章では curl で ECR push / `run-task` / `describe-tasks` 確認までを範囲とする。

## k8s manifests (`k8s-manifests/`)

`base/deployment.yaml`:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata: { name: api }
spec:
  replicas: 2
  selector: { matchLabels: { app: api } }
  template:
    metadata: { labels: { app: api } }
    spec:
      containers:
      - name: api
        image: demo-api:v1
        imagePullPolicy: IfNotPresent
        ports: [{ containerPort: 8080 }]
        env:
        - name: APP_VERSION
          valueFrom: { configMapKeyRef: { name: api-config, key: version } }
```

加えて Service / Ingress / HPA / ConfigMap / PVC を提供。

## Makefile (10-3 root)

```makefile
.PHONY: localstack-up ecr-push ecs-deploy ecs-run kind-up kind-deploy compare verify down

localstack-up:
	docker compose -f localstack/docker-compose.yml up -d
	sleep 3

ecr-push:
	./localstack/seed.sh

ecs-deploy:
	cd terraform/ecs && terraform init && terraform apply -auto-approve -var="endpoint=http://localhost:4566"

ecs-run:
	aws --endpoint-url=http://localhost:4566 ecs list-tasks --cluster learning-ecs
	aws --endpoint-url=http://localhost:4566 ecs describe-tasks --cluster learning-ecs --tasks $$(aws --endpoint-url=http://localhost:4566 ecs list-tasks --cluster learning-ecs --query 'taskArns[0]' --output text)

kind-up:
	kind create cluster --name learning-ecs-vs-k8s

kind-deploy:
	docker build -t demo-api:v1 demo-app/api
	kind load docker-image demo-api:v1 --name learning-ecs-vs-k8s
	kubectl apply -k k8s-manifests
	# 注: k8s-manifests/base/deployment.yaml の image は `demo-api:v1` (kind load で投入済)。
	#     LocalStack 側の ECR URL とは別物。同一の image 内容を別レジストリ識別子で扱う。

compare:
	@echo "=== ECS (LocalStack) ==="
	$(MAKE) ecs-run
	@echo "=== k8s (kind) ==="
	kubectl get deploy,svc,ingress,hpa
	kubectl exec deploy/api -- curl -fsS http://localhost:8080/api/v1/echo || true

verify:
	$(MAKE) localstack-up
	$(MAKE) ecr-push
	$(MAKE) ecs-deploy
	$(MAKE) kind-up
	$(MAKE) kind-deploy
	$(MAKE) compare

down:
	cd terraform/ecs && terraform destroy -auto-approve -var="endpoint=http://localhost:4566" || true
	docker compose -f localstack/docker-compose.yml down -v || true
	kind delete cluster --name learning-ecs-vs-k8s || true
```
